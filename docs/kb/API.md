# Поточний HTTP API

Реалізація: [server.py](../../backend/server.py). Звичайний ThreadingHTTPServer, без авторизації. Використання — власний ПК у довіреній мережі; це не готовий публічний сервіс.

## GET /health

HTTP 200:

```json
{"status":"ok","ai":"multinomial-naive-bayes-v1"}
```

Цей endpoint існує; окремої кнопки його перевірки в Android ще немає.

## POST /v1/cards

Content-Type клієнта: application/json; charset=utf-8. Максимальний body за Content-Length — 22 МіБ. Тіло повинно бути JSON-об'єктом.

```json
{
  "partNumber": "BZX84C2V4LT1G",
  "url": "https://www.onsemi.com/pdf/datasheet/bzx84c2v4lt1-d.pdf"
}
```

Альтернатива: `pdfBase64` замість `url`. Обирається рівно одне непорожнє джерело. Для файла Android надсилає весь PDF як base64 у JSON, не multipart.

Перевірки:

- partNumber після обрізання пробілів: 1–100 символів, латинські букви, цифри, `_ . / + ( ) -` та пробіл.
- URL: HTTPS, порт 443 або стандартний, без облікових даних; DNS-адреси мають бути публічними; redirect перевіряється повторно. Це захисна перевірка, не повна гарантія від DNS rebinding.
- Тайм-аут URL-завантаження — 25 с.
- PDF до 15 МіБ, початок `%PDF-` після пробільних байтів; без шифрування; 1–100 сторінок.
- Сумарно щонайменше 100 непробільних за обрізанням країв символів текстового шару. Скани без тексту не підтримуються.

Успіх — HTTP 200. Основні поля:

| Поле | Поточне значення/сенс |
| --- | --- |
| schemaVersion | 1 |
| partNumber | Артикул із запиту |
| classification | type, label, method, unverified |
| documentId | SHA-256 вихідних PDF-байтів |
| pageCount | Кількість сторінок |
| evidence | До 12 об'єктів page/quote/status |
| partFound | Знайдено нормалізоване входження артикула |
| status | unverified |
| summary | Фіксований український текст, не згенерований LLM |
| parameters | Завжди [] у поточній версії |
| limitations | Два повідомлення про відсутність розбору параметрів і малий навчальний набір |

Кожна evidence містить фізичну сторінку від 1 та фрагмент до 1800 символів: рядок перед збігом, рядок збігу та два наступні. На сторінку повертається максимум один фрагмент. Пошук прибирає пунктуацію і регістр та перевіряє substring; це не точна перевірка артикула/рядка таблиці. Немає збігу — HTTP 200, partFound=false та порожні evidence, а не 404.

## GET /documents/{documentId}.pdf

documentId має складатися з 64 малих hex-символів. Успіх — HTTP 200, application/pdf. Відсутній файл — 404. Сервер зберігає PDF у storage незалежно від того, чи знайшов артикул. Параметр сторінки Android додає у fragment `#page=N`, який не передається серверу.

## Помилки

```json
{"error":"Текст повідомлення"}
```

| Код | Причина |
| --- | --- |
| 400 | ValueError/TypeError/AttributeError при валідації або обробці запиту |
| 422 | Інші помилки завантаження/читання PDF; повертається загальне повідомлення |
| 404 | Невідомий маршрут або відсутній документ |

Окремої схеми помилок із машинними error codes немає. Справжній мережевий збій на Android може показувати повідомлення винятку англійською.

## Відомі межі

Немає auth, rate limit, ізоляції PDF-парсера та ліміту паралельних задач. Артикул на кшталт `---` проходить дозволені символи, але після нормалізації порожній і помилково збігається з усіма сторінками. Дефект знайдено під час аудиту KB, не виправлено в цьому таску.
