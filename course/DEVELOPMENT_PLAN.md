## Прив’язка до лабораторних

| Робота | Що відомо | Наступна дія |
| --- | --- | --- |
| №1 | Налаштування середовища та концепція додатка | Перевірити звіт, додати власні скріншоти, закрити роботу |

| Наступні | Теми й кількість робіт невідомі | Розподілити етапи після отримання вимог |

Номери лабораторних не прирівнюємо до номерів етапів нижче. Це послідовність розвитку продукту; конкретні роботи можуть вимагати іншого порядку. Не додаємо функції лише для кількості й не пишемо звіт про невиконане.

- [x] Отримати вимоги.

- [ ] Запустити backend на власному ПК, без хмарної передачі PDF; доступ із телефона по локальній мережі.
- [ ] Один сценарій: ввід фрагмента тексту даташита й артикула → HTTP → перевірка → реальний простий AI-компонент → чернетка картки → мобільний екран.
- [ ] Реалізувати стани завантаження, результату й помилки, включно з відсутнім backend.
- [ ] Перевірити з'єднання з емулятора або телефона та зробити докази повного потоку.
- [ ] Написати звіт про фактично виконаний сценарій.

Це пропозиція MVP: повний PDF, менеджер моделей і локальний inference на Pixel 8 не обов'язкові для демонстрації одного сценарію. AI-компонент не підмінюється простим пошуком ключових слів. Його конкретний варіант ще не обрано.

Важливо: backend на своєму ПК не є хмарою, але PDF/текст покидає телефон. Це відступ від раніше погодженого phone-only режиму, який потребує рішення користувача. Релізний локальний адаптер залишається в плані; HTTP-адаптер потрібен для вимог курсу. Порядок попередніх етапів тепер коригується: для №2 один AI-сценарій потрібен до завершення всього набору калькуляторів.

Готово, коли є зрозумілий обсяг роботи №2. До цього не називаємо архітектурні або програмні зміни виконанням лабораторної №2.

## Етап 3. Початкові калькулятори

Виконуємо послідовно, завершуючи один інструмент перед наступним:

1. Вирази та інженерні одиниці.
2. Стандартні номінали E12/E24/E96.
3. Ручний конструктор послідовно-паралельних резисторних мереж.
4. Допуски й порівняння точності.
5. RC-фільтри та графік АЧХ.
6. Маркування, з’єднання конденсаторів, частота/період/фаза.

Для кожного: формули й межі → розрахунок із контрольними прикладами → екран → перевірка на телефоні. Автопідбір мереж до шести резисторів — окреме розширення після ручного редактора.

## Етап 5. Локальна AI-картка — після основи калькуляторів

1. Підготувати ручну картку та перегляд текстового PDF зі сторінками.
2. Реалізувати шаблони діода, резистора, конденсатора й дроселя.
3. Вибрати контрольні PDF з відомими правильними параметрами.
4. Перевірити кандидатів локальних моделей на звичайному Pixel 8.
5. Додати каталог, завантаження, перевірку й видалення моделей.
6. Зв’язати PDF → фрагменти → структуровані параметри → українську картку.
7. Зберігати PDF, min/typ/max, умови, сторінки й позначки неперевірених даних офлайн.

Готово, коли повний сценарій створює перевірювану картку без передавання PDF в інтернет. Спочатку точний артикул; за потреби — картка сімейства. Чат, OCR і автоматичне заповнення калькуляторів сюди не входять.

## Етап 6. Розширення

Після основи окремо вибираємо наступний модуль із FEATURE_CHECKLIST.md: автопідбір резисторів, NTC, шунти, сигнали, RF або PCB. Не запускаємо всі напрями одночасно.

Версію для ПК перевіряємо невеликим прикладом під час визначення спільного UI; повну реалізацію робимо після стабілізації Android. Далі можливі запитання до PDF та передавання перевірених параметрів у калькулятори.
